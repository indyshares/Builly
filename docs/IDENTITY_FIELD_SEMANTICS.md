# Builly identity field semantics

| Field | Meaning | Source of truth |
|---|---|---|
| `accounts.id` | Builly Account ID; internal ownership key used by all D1 `owner_id` columns | Generated by Builly on first login, or adopted from an explicit legacy mapping |
| `external_identities.subject` | Stable Google OIDC `sub` | Google ID token, verified by Worker JWKS |
| `workspace_credentials.google_oidc_sub` | Stable Google OIDC `sub` attached to the encrypted Workspace credential | Google ID token at login/reconnect (migration `0006`) |
| `workspace_credentials.google_subject` | Legacy Drive principal (`permissionId` or email) used by the old Workspace flow | Drive `/about` response; never treated as identity |

Rules:

- Never assume Drive `permissionId` equals Google OIDC `sub`.
- Reconnect that supplies no OIDC subject must not overwrite a stored `google_oidc_sub` (SQL `CASE WHEN excluded.google_oidc_sub = '' …`).
- Identity lookups use only `(provider, subject)` → `account_id`. Email is metadata, never a merge key.
- Workspace disconnect deletes only the credential row; the Builly Account and its identity mappings remain.

Migration `0006_identity_subject_separation.sql` is additive: one new column and one index. No existing value is rewritten or deleted.
